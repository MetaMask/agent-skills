# Manifest in package.json

Two blocks must agree with the TypeScript commands.
`oclif` handles discovery.
`mm` handles permissions.

## oclif

```json
{
  "keywords": ["oclif-plugin"],
  "oclif": {
    "bin": "mm",
    "commands": "./dist/commands",
    "topicSeparator": " ",
    "topics": {
      "hello": {
        "description": "Example commands from the plugin template"
      }
    }
  }
}
```

Do not set `oclif.hooks` or `oclif.plugins`.
The host rejects the install with `PLUGIN_HOOKS_FORBIDDEN`.

## mm schema

`schemaVersion` must be `1`.

```json
{
  "mm": {
    "schemaVersion": 1,
    "minCliVersion": "^6.2.0",
    "capabilities": [],
    "commands": [
      {
        "id": "hello:ping",
        "capabilities": [],
        "dataAccess": []
      }
    ]
  }
}
```

`minCliVersion` is a semver range checked against the running CLI version.
A mismatch returns `PLUGIN_CLI_VERSION`.

Keep plugin-wide `capabilities` as an empty array.
The host merges that list into every command.

`commands` needs at least one entry.
Every loadable command id must appear here.

Each command `id` is colon-separated and must match `pluginCommandId`.

Each command `capabilities` value is a subset of `wallet-read`, `wallet-submit`, and
`network-manage`.

Each command `dataAccess` value is a consent label from `accounts`, `balances`,
`prices`, `tokens`, `network`, `fees`, `swap-quotes`, `session`, and `mnemonic`.

`targetChains` defaults to `"any"`.
You can also pass an array of numeric chain IDs.

The catalog skips undeclared command ids in `dist/`.
It also skips ids that collide with built-in host commands.

## Build artifact

`oclif.manifest.json` is generated by `oclif manifest`.
Published packages must include it.
If the file is missing, install rolls back with `PLUGIN_MANIFEST_FILE_MISSING`.

## Peer dependency

```json
{
  "peerDependencies": {
    "@metamask/agent-wallet": "^6.2.0"
  }
}
```

At runtime the host peer-links the running CLI.
Do not bundle a second copy of the CLI into the plugin.
